# Sfeed — Cloudflare Edge & Workers AI 기반 멀티유저 RSS 서비스

**Sfeed**는 Feedly에서 영감을 받아 제작된 모던 멀티유저 RSS 큐레이션 플랫폼입니다. **React (Vite) + Hono + Cloudflare D1 (SQLite) + Cloudflare Workers AI** 스택으로 구축되어 GitHub과 Cloudflare만으로도 서버 비용 걱정 없이 배포할 수 있습니다.

---

## ✨ 주요 기능

1. **Google 로그인 & 멀티유저 격리 (Cloudflare D1)**
   - Google OAuth 2.0 인증 지원 (`GOOGLE_CLIENT_ID` 연동 시 정식 리다이렉트 동작)
   - 이메일만으로 로그인하는 빠른 계정 전환은 **로컬 개발 환경에서만** 동작합니다 (`npm run dev`에서는 기본 활성화, `wrangler dev`에서는 `.dev.vars`에 `ALLOW_QUICK_LOGIN="true"` 설정). 배포 환경에서는 API가 403을 반환하고 UI도 숨겨집니다.
   - 사용자별 폴더, 피드 구독, 읽음/안읽음 상태, 북마크(Read Later), 테마·레이아웃 설정이 D1에 독립 저장
2. **카테고리(폴더) 관리 & 추천 피드 카탈로그**
   - 신규 가입 시 빈 구독 목록으로 시작하며, 추천 피드 카탈로그에서 원하는 피드만 직접 구독 (선택한 피드의 추천 폴더도 함께 생성)
   - 긱뉴스(GeekNews), 토스 테크, 우아한형제들, 카카오테크, Cloudflare Blog, Hacker News, OpenAI News 등 엄선된 카탈로그 원클릭 구독
   - 추천 피드 카드를 누르면 최근 글 최대 10개의 제목·요약을 미리 확인하고, 원하는 피드만 선택해 구독
   - 일반 웹사이트 주소만 입력해도 RSS/Atom 피드 링크 자동 탐색(Auto-discovery)
   - RSS가 없는 사이트는 **RSS 빌더로 만들기**에서 글 목록을 미리보고 선택해 구독합니다. 생성된 RSS 주소는 OPML로 내보낼 수 있고, 수동 새로고침과 15분 주기 갱신으로 새 글을 수집합니다.
   - 동적 페이지에는 Cloudflare Browser Rendering 바인딩(`BROWSER`)을 사용합니다. 로그인·보안 확인이 필요한 페이지는 수집하지 못할 수 있습니다. 발행일이 없는 글에는 임의의 발행일을 표시하지 않습니다.
3. **Feedly 스타일 3종 레이아웃 & 다크/라이트 모드**
   - **매거진 뷰 (Magazine View)**: 썸네일 + 핵심 요약 중심의 기본 레이아웃
   - **카드 뷰 (Cards View)**: 커버 이미지 중심의 반응형 그리드 레이아웃
   - **리스트 뷰 (Title-Only Compact View)**: 한눈에 수십 개의 헤드라인을 스캔하는 고밀도 리스트
   - 키보드 단축키 지원 (`J`/`K` 이동, `M` 읽음 토글, `S` 북마크, `R` 새로고침, `A` 모두 읽음, `Q`/`W` 선택한 글 위·아래 모두 읽음, `ESC` 닫기). 모두 읽음 단축키는 확인 창을 띄우고 `Enter`로 확정합니다.
4. **원문 전체 본문 스크래핑 (Reader View)**
   - 요약만 제공하는 RSS 피드도 아티클 뷰어 내 **원문 전체 불러오기** 버튼으로 웹페이지 본문을 추출·정제하여 광고 없이 열람
5. **Cloudflare Workers AI 한국어 핵심 요약**
   - 아티클 뷰어의 **AI 핵심 요약** 버튼 클릭 시 Cloudflare Workers AI(`@cf/meta/llama-3.1-8b-instruct`)를 호출하여 **한줄 요약 + 주요 포인트 3가지 + 키워드**를 생성하고 D1에 캐싱
6. **OPML 2.0 가져오기 / 내보내기**
   - 기존 Feedly, Inoreader 등의 `.opml` 파일을 업로드해 폴더 구조 그대로 일괄 구독하거나, 내 구독 목록을 `.opml`로 백업
   - 60개 제한 없이 전체 목록을 작은 요청으로 나누어 처리하고, 신규·기존 구독·실패 건수와 진행률을 표시
   - 같은 화면에서 일시 중단 후 이어서 가져오기, 실패한 피드만 재시도 지원. 화면을 닫거나 새로고침했다면 같은 파일을 다시 선택해도 기존 구독은 중복 추가되지 않음
   - 실패 항목의 주소·폴더·오류·시도 횟수를 계정별 D1에 저장하며, 다시 로그인해도 확인 가능. 주소 수정·연결 확인·재시도를 지원하고 성공한 항목은 실패 목록에서 제거
   - 확인된 대체 피드는 직접 선택해 적용하며, 발행 범위가 다른 뉴스레터로 자동 변경하지 않음
   - **X 팔로우** 탭에서 X 로그인으로 현재 팔로우 목록을 페이지별로 불러오고, 원하는 공개 계정만 선택해 폴더에 구독합니다. 조회만으로 구독하지 않으며 비공개 계정은 제외합니다. 진행 중 중단·이어받기와 계정 검색을 지원하고, 구독 실패는 기존 계정별 실패 목록에 저장합니다.
   - 개별 계정은 검색창에 `@NASA`, `https://x.com/NASA`, `https://twitter.com/NASA`처럼 입력해 미리보고 구독할 수 있습니다. 공개 게시물은 Nitter의 RSS에서 읽으며, 원래 X 링크·발행일·사진을 보존합니다. 외부 제공 경로가 중단되거나 요청 제한을 반환하면 오류를 표시하고 제한 중 재요청하지 않습니다. 비공개 게시물과 과거 전체 기록은 가져오지 않습니다.
   - RSS 한 번은 최신 글 약 20개만 주므로, 15분마다 도는 정기 새로고침 뒤에 미러가 알려 주는 다음 쪽으로 계정마다 예전 글을 한 쪽(약 20개)씩, 한 번에 최대 10쪽 채웁니다. 계정마다 첫 쪽을 포함해 10쪽(약 200개)까지 받고, 미러가 요청 제한을 알리면 그 자리에서 멈췄다가 다음에 이어 받습니다. 뒤늦게 채운 예전 글은 읽은 글로 둡니다. 새로고침 사이에 20개 넘게 올라와 첫 쪽이 모두 새 글이면, 이미 받은 글이 나올 때까지 다음 쪽을 최대 3쪽 더 받아 빠진 글을 채웁니다. 기존 운영 DB에는 `migrations/0006_x_backfill.sql`을 한 번 적용해야 하며, 적용 전에는 예전 글 채우기만 쉬고 빠진 글 채우기는 그대로 동작합니다.
   - 공개 RSS는 최대 5분·4MB만 서버 메모리에서 재사용하고 갱신 동시 실행을 2개로 제한합니다. 받은 게시물은 기존 계정별 기기 캐시를 이용합니다. X 로그인 토큰은 서버 키로 암호화한 짧은 연결 정보로만 전달하고, 영구 DB나 기기 로컬 저장소에 보관하지 않습니다. 팔로우 변경을 가져오려면 다시 연결합니다.
7. **Feedly 과거 기록 가져오기 (1회성 스크립트)**
   - RSS는 최신 글 일부만 담으므로, Feedly 공개 스트림에서 구독 피드의 전체 기록(제목·요약·링크·썸네일·날짜)을 받아 저장합니다. 기존 글과는 원래 글 ID로 맞춰 중복 없이 합칩니다.
   - `npm run import:feedly -- download --db remote --user <userId>` 로 `.local/feedly-import/`에 내려받고(이어받기 지원), `npm run import:feedly -- write --db remote --user <userId>` 로 D1에 기록합니다.
   - `npm run import:feedly:sync -- --db remote --user <userId>` 는 다운로드와 10분 간격 D1 반영을 함께 실행합니다. 다운로드 중이거나 요청 제한으로 대기 중이어도 이미 받은 글을 반영하며, 다운로드 진행과 DB 반영 위치는 별도 파일에 저장합니다.
   - 요청 간격은 최소 5초이며, 429 응답의 `Retry-After`·`X-Ratelimit-Reset`을 따릅니다. 반복 제한 시 15분부터 최대 6시간까지 대기를 늘리고(서버가 더 긴 시간을 요구하면 해당 시간을 적용), 재시작해도 대기 시각을 유지합니다.
   - 정상 요청은 **5초 간격**으로 받고, 기본 실행에는 자체 일일 한도를 두지 않습니다. Feedly가 실제로 한도 도달 또는 429를 알리면 해당 대기 시간을 지킵니다. 필요하면 `--requests-per-day <횟수>`로 최근 24시간 자체 예산을 설정할 수 있고, `0`은 자체 한도 해제입니다. 실패·재시도도 요청 이력에 포함하고 서버의 한도·초기화 헤더를 저장합니다.
   - 미완료 피드들은 한 페이지씩 번갈아 받으므로 큰 피드 때문에 다른 피드가 계속 대기하지 않습니다. 이미 서버에 반영한 분량뿐이라면 불필요한 DB 조회도 생략합니다.
   - Feedly처럼 30일이 지난 글은 따로 표시하지 않아도 읽은 글로 취급하며, 안읽음 수·안읽음 필터·모두 읽음은 최근 30일 글만 대상으로 합니다.
8. **기기 캐시와 변경분 동기화**
   - 매거진·카드 목록은 화면 가까운 글의 누락된 썸네일을 최대 4개씩 보완 조회합니다. 찾은 주소는 계정별 기기 캐시에 보관하고 목록에도 반영합니다. 실제 이미지가 없을 때는 사이트 로고를 쓰며, 일시적인 접속 실패·요청 제한은 영구적인 이미지 없음으로 저장하지 않습니다.
   - 최근 폴더·개수·글 목록은 계정별 IndexedDB에 최대 160개 화면·32MB·기본 30일 보관합니다. 동기화는 모든 폴더의 첫 화면까지 준비한 뒤 끝나므로 새로고침 아이콘이 멈추면 폴더가 바로 열립니다. 로그아웃해도 남겨두고 같은 계정 인증 후 다시 사용합니다. 다른 계정 데이터는 표시하지 않습니다.
   - 초기 조회 뒤 자동 확인은 `/api/sync`로 변경 번호만 확인합니다. 변경과 날짜 경계가 없으면 로그인 확인·변경 번호 조회 두 번만 실행하며, 글 목록과 COUNT 집계를 실행하지 않습니다. 변경된 글·상태·폴더만 받아 로컬 목록에 반영하고, 개수는 바뀐 피드와 24시간 범위만 다시 확인합니다. 24시간/30일 읽음 기준이 지나면 해당 개수도 갱신합니다.
   - 캐시된 탭 전환은 기기에서 처리합니다. 새로운 목록은 첫 화면만 조회하고, 목록·RSS 본문은 수신할 때 보관합니다. 화면 가까운 글은 피드별 보기 방식에 맞춰 준비하며, 웹 사본은 최대 2개·리더 본문은 1개씩 미리 받습니다. 읽는 글의 다음 2개도 준비하고 데이터 절약 모드에서는 미리받지 않습니다. 리더·웹 사본은 계정별 IndexedDB에 별도 보관해 재실행에도 재사용합니다. 썸네일을 찾는 동안과 이미지가 없는 글에는 사이트 로고를 표시합니다.
   - 웹 사본을 처음 준비할 때는 웹 탭을 유지하며 이미 받은 제목·본문을 먼저 보여줍니다. 미리보기를 스크롤하며 읽기 시작한 경우에는 원문이 준비돼도 위치를 바꾸지 않고 **웹 페이지 보기**로 전환할 수 있습니다. 캐시된 사본의 반복 HTML 가공도 피하며, 서버의 기사 렌더링은 광고 요청 완료가 아닌 본문 준비를 기다립니다.
   - 읽음·저장은 기기에 즉시 반영하고 서버에는 변경만 저장합니다. 스크롤 읽음은 여러 글을 묶어 저장합니다. 이전 화면·계정의 늦은 응답은 적용하지 않습니다.
   - 서버 변경 기록은 본문을 복사하지 않고 항목별로 합치며 최대 50,000개 버전 범위로 정리합니다. 오래된 커서나 대량 가져오기 이후에는 현재 스냅샷 한 번으로 복구합니다. 운영 반영 전 `migrations/0002_reader_sync.sql`을 적용해야 합니다. 로컬 개발 DB는 해당 파일을 자동 적용합니다.
   - 전체·안 읽음·저장 탭의 첫 20개 글은 현재 화면을 먼저 표시한 뒤 하나씩 미리 받습니다. 유효한 캐시가 있는 탭은 재다운로드하지 않습니다. 검색 입력은 200ms 대기 후 처리합니다.
   - 모바일·데스크톱 자동 확인 주기는 수동·1·5·10·15·30·60분이며 기본 15분입니다. 원본 RSS 수집은 기존 15분 주기를 유지합니다. 알림이 꺼져 있으면 숨긴 탭의 확인도 멈춥니다.
   - **새 글 제목 알림**은 이 기기에서 권한을 허용하고 켭니다. 실행 중인 앱이 변경분에서 새 글을 발견하면 피드명과 글 제목을 표시합니다. 맥에서는 `피드명 · 글 제목`을 제목 영역에 묶고 본문을 비워 브라우저의 출처 표시가 둘 사이에 끼지 않게 합니다. 모바일은 피드명 아래에 글 제목을 표시합니다. 피드명이 없으면 SFeed로 표시합니다. 서버 푸시·구독·VAPID 키를 사용하지 않습니다. 앱을 완전히 종료하면 감지하지 못하고 백그라운드 실행은 OS가 중단할 수 있습니다. 아이폰은 홈 화면에 설치한 앱에서 알림 권한을 허용해야 합니다.
   - 안 읽음 탭에서는 안 읽은 글이 0개인 폴더·피드를 숨깁니다. 모바일·데스크톱 안 읽음 목록은 읽은 글을 흐리게 남겨두고 목록 재진입이나 새로고침 때 제외합니다. 스크롤 읽음으로 행을 제거하지 않으며 동기화로 위쪽에 글이 추가돼도 보던 위치를 유지합니다. 폴더 화면 설정에서는 스크롤 읽음 옵션을 숨깁니다.
   - **업데이트 중지**는 구독을 유지한 채 피드의 새 글만 그만 받습니다. 모바일은 피드를 길게 누르거나 라이브러리 편집 모드의 일시정지 버튼, 데스크톱은 우클릭 메뉴나 피드 행의 일시정지 버튼을 씁니다. 받은 글과 읽음·저장 기록은 남고, 중지한 뒤 들어온 글은 목록·개수·동기화·알림에서 빠집니다. 다시 받으면 중지 동안의 글은 읽은 글로 표시합니다. 같은 피드의 다른 구독자는 영향을 받지 않습니다. 기존 운영 DB에는 `migrations/0004_subscription_pause.sql`을 한 번 적용해야 하며, 적용 전에는 이 기능만 사용할 수 없고 나머지는 그대로 동작합니다.
   - 데스크톱 필터 탭은 표시 범위와 숫자만 바꾸고 **전체 글** 메뉴로 해당 목록을 엽니다. 보기 방식은 환경설정에 있으며, 상단 정렬 버튼은 최신순/오래된순을 바로 전환합니다(기본 최신순). 폴더 접힘은 계정별로 기기에 보관합니다.
   - 데스크톱 우클릭과 모바일 글·피드·폴더 길게 누르기는 앱 메뉴를 엽니다. 읽음·저장·원문 열기·링크 복사 등을 지원하며 삭제·모두 읽음은 기존 확인 절차를 거칩니다. 입력창과 모바일 본문 텍스트 선택은 기본 동작을 유지합니다.
   - 모바일 목록 맨 위에서 아래로 당겼다가 놓으면 피드를 새로고침합니다. 기존 목록과 진행 표시를 유지하고 중복 실행을 막습니다.
   - 본문 보기(피드·리더·웹)는 피드별로 계정에 저장하고 모바일·데스크톱 간 변경분 동기화로 공유합니다. 기존 기기 선택은 해당 피드를 열 때 공통 선택이 비어 있는 경우에만 옮깁니다. 목록 보기·화면 설정·읽음 필터·갱신 주기·웹 줌은 기존처럼 계정별 기기에 저장하며 데스크톱·모바일 프로필을 분리합니다.
   - 본문·웹 사본은 최대 256MB, 메모리 보관은 16MB로 제한합니다. 설정에서 1·7·14·30·60·90일 보관 기간과 추정 사용 용량을 확인하고 해당 계정의 캐시를 수동 삭제할 수 있습니다. 만료 데이터는 열 때 사용하지 않고 앱 실행·사용 중 정리합니다. 삭제 뒤 늦게 끝난 미리받기가 캐시를 다시 만들지 못하도록 차단합니다.
   - CoinDesk 웹 보기는 기기가 Jina Reader의 공개 HTML을 직접 받아 준비합니다. 날짜가 포함된 CoinDesk 기사 주소만 허용하고 쿼리·인증정보·쿠키는 전달하지 않습니다. 기기에서 스크립트·프레임을 제거하고 본문·스타일·사진을 유지한 사본을 선택한 보관 기간 동안 재사용합니다. 재열람에는 서버 요청이 없고, 직접 가져오기가 실패하면 기존 서버 사본 경로를 시도하며 실패·보안 확인·유료 전용 페이지는 저장하지 않습니다.
   - 웹 보기는 원본을 즉시 시도하고, 직접 표시가 차단되면 공개 페이지 사본과 브라우저 렌더링을 시도합니다. 웹 모드를 자동으로 리더로 바꾸지 않습니다. 사본의 링크·스타일은 유지하고 스크립트는 제거하며 별도 sandbox로 표시합니다. 원본의 로그인·보안 확인이나 동적 댓글까지 재현하지는 않습니다.
   - 로그인 세션은 1년이며 사용 시 만료가 180일 이내이면 1년으로 갱신합니다. 기존 30일 세션도 다음 요청에 연장하고, 로그아웃·만료된 세션은 재활성화하지 않습니다. 일시적인 연결·서버 오류로 토큰을 지우지 않고 동일 세션에서 마지막으로 검증한 프로필과 기기 캐시를 사용합니다.
   - 내용 해시가 포함된 JS/CSS는 장기 캐시하고 HTML·서비스 워커·manifest는 최신 버전을 확인합니다. 서비스 워커는 로그인/API 응답을 저장하지 않습니다.

## ☁️ GitHub + Cloudflare 배포 가이드

### 1단계: Cloudflare D1 데이터베이스 생성 및 스키마 적용
```bash
# Cloudflare 로그인
npx wrangler login

# D1 데이터베이스 생성
npx wrangler d1 create sfeed-db
```
출력된 `database_id` 값을 [wrangler.toml](file:///Users/jongyoon/Documents/Projects/Sfeed/wrangler.toml)의 `database_id` 항목에 붙여넣은 뒤, 원격 DB에 테이블을 생성합니다:

```bash
npm run db:migrate:remote
```

### 2단계: Google 로그인 설정
Sfeed는 Google Identity Services(GIS) 버튼으로 ID 토큰을 받아 서버에서 RS256 서명을 검증합니다. 리디렉션 URI와 클라이언트 보안 비밀번호는 필요하지 않습니다.
1. Google Cloud의 [Google 인증 플랫폼](https://console.cloud.google.com/auth/clients)에서 **OAuth 클라이언트 ID (웹 애플리케이션)**를 생성합니다. (현재: SFeed 프로젝트의 `Sfeed Web` 클라이언트)
2. **승인된 JavaScript 원본**에 아래 주소를 추가합니다:
   - 배포: `https://sfeed.jyk.workers.dev`
   - 로컬: `http://localhost:5173`, `http://localhost`
3. 발급된 클라이언트 ID를 `wrangler.toml`의 `GOOGLE_CLIENT_ID`에 넣습니다. 로컬에서는 `.dev.vars`로 덮어쓸 수 있습니다.
4. 외부 사용자가 로그인하려면 **브랜딩**에 홈페이지, 개인정보처리방침 링크(`https://sfeed.jyk.workers.dev/privacy`), 승인된 도메인(`jyk.workers.dev`)을 입력한 뒤 **대상** 페이지에서 앱을 게시합니다.

### X 로그인 연동 설정 (선택)

X 팔로우 목록 자동 가져오기는 [X 개발자 앱](https://developer.x.com/) 설정이 필요합니다. OAuth 로그인과 별도로 팔로우 조회 API의 이용 권한·요금이 적용됩니다. 최초 설정 전에도 운영자의 **X 로그인 · 연결 설정** 버튼은 활성화되며, 누르면 X 로그인 창과 SFeed의 설정 안내가 열립니다. 개별 공개 계정 주소로 구독하는 기능은 별도 키 없이 사용할 수 있습니다.

1. 개발자 콘솔에서 앱을 만들고 OAuth 2.0을 켭니다. 앱 유형은 서버에서 비밀키를 사용하는 **Web App**으로 설정합니다.
2. Callback URI를 `https://sfeed.jyk.workers.dev/?x_callback=1`로 정확히 등록합니다. 로컬 테스트에는 `http://localhost:5173/?x_callback=1`을 별도로 등록합니다.
3. 읽기 권한을 허용합니다. 로그인 시 요청하는 범위는 `tweet.read users.read follows.read`이며, 쓰기·DM·오프라인 갱신 권한은 요청하지 않습니다.
4. SFeed의 **피드 추가 → X 팔로우**에서 OAuth 2.0 Client ID와 Client Secret을 입력한 뒤 **저장하고 X 계정 연결**을 누릅니다. 서버에 암호화해 저장한 뒤 계정 연결로 바로 이어집니다. 설정 완료 후에는 **X 계정 연결** 버튼으로 로그인합니다.

화면 설정은 `OWNER_EMAIL`과 일치하는 운영자 계정만 사용할 수 있습니다. `migrations/0005_x_connection_settings.sql`을 적용하고 서버 비밀값 `X_SETTINGS_SECRET`에 32자 이상의 무작위 값을 등록해야 합니다. 암호화 키는 DB와 분리하며 Client Secret은 API 응답·기기 저장소에 남기지 않습니다. 로컬 개발 DB는 마이그레이션을 자동 적용합니다.

기존처럼 환경 변수로 관리하려면 다음 명령을 사용할 수도 있습니다. 환경 변수로 두 키가 모두 설정돼 있으면 화면에서 덮어쓰지 않습니다.

```bash
npx wrangler secret put X_CLIENT_ID
npx wrangler secret put X_CLIENT_SECRET
```

로컬에서는 같은 이름을 `.dev.vars`에 넣을 수 있습니다. 로그인한 뒤 가져올 계정을 선택합니다. 조회는 최대 1,000개씩 이어지고 구독은 계정당 한 요청으로 처리합니다. 로그인 취소·만료·API 잔액/권한 부족은 화면에 알리며 자동으로 과금 요청을 반복하지 않습니다.

### 3단계: 배포하기 (GitHub 자동 배포 또는 CLI 배포)
- **CLI 직접 배포:**
  ```bash
  npm run cf:deploy
  ```
- **GitHub 연동 자동 배포 (Workers Builds):**
  1. 이 프로젝트를 GitHub 저장소에 푸시합니다.
  2. Cloudflare 대시보드에서 **Workers & Pages -> sfeed -> Settings -> Builds -> Connect**로 GitHub 저장소를 연결합니다. (워커가 아직 없다면 **Create -> Import a repository**)
  3. Build command: `npm run build` / Deploy command: `npx wrangler deploy`로 설정하면 `main`에 `git push`할 때마다 자동 배포됩니다.
  4. GitHub의 **Cloudflare Workers and Pages** 앱이 "Only select repositories"로 설치되어 있다면 **GitHub Settings -> Applications -> Cloudflare Workers and Pages -> Configure**에서 이 저장소를 추가해야 합니다. 빠져 있으면 Cloudflare에서 저장소 선택은 되지만 푸시 이벤트를 받지 못해 빌드가 시작되지 않습니다.
