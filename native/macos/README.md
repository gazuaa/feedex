# FeedEx for Mac

앱 전체 배율은 기본 90%이며, 환경설정의 ‘앱 화면 크기’ 또는 보기 메뉴에서 조절한다.
배율은 이 맥의 UserDefaults에만 저장한다. 기사 글자 크기와 피드별 웹 보기 배율은 별도다.

2.3부터 Sparkle로 앱 내부에서 업데이트한다. FeedEx 메뉴와 환경설정의 ‘업데이트 확인’이 같은 기능을 연다.
자동 확인은 켜져 있고 자동 설치는 꺼져 있다. 사용자가 설치를 선택하면 앱 교체와 재실행을 Sparkle이 처리한다.
2.2 이하에는 업데이트 기능이 없으므로 2.3으로 한 번 수동 교체해야 한다.

## 새 버전 배포

1. `Info.plist`의 버전과 빌드 번호를 모두 올리고 `src/shared/macApp.ts` 버전을 맞춘다.
2. 업데이트 개인 키가 `.local/keys/update-ed25519`에 있는 이 맥에서 `./scripts/build-macos-reader.sh`를 실행한다.
   다른 안전한 경로를 사용하면 `FEEDEX_UPDATE_KEY_FILE`로 지정한다.
3. `npm run test:native-app`과 `npm run build`를 통과시킨다.
4. 새 버전 zip, 기본 다운로드 zip, 서명된 appcast.xml, 소스 지문을 함께 배포한다.
   기존 버전 이름의 zip은 바꾸거나 덮어쓰지 않는다. 업데이트 피드는 항상 최신 한 버전을 가리킨다.

빌드는 고정한 SHA-256으로 공식 Sparkle 배포판을 확인하고 앱 안에 프레임워크를 포함한다.
아카이브와 appcast 모두 Ed25519로 서명한다. 앱은 내려받은 파일을 압축 해제하기 전에 검증한다.
개인 키는 저장소에 포함하지 않으며, 서버에도 보내지 않는다. 파일 권한은 600, 키 폴더 권한은 700이다.
개인 키를 잃으면 기존 앱의 업데이트 서명을 만들 수 없으므로 안전하게 백업해야 한다.

## 최초 키 생성 (새 앱을 처음 배포할 때만)

`xcrun swift scripts/update-signing-key.swift --create .local/keys/update-ed25519`

출력은 공개 키뿐이다. 이 공개 키를 Info.plist의 SUPublicEDKey에 넣는다.
기존 앱을 배포한 뒤에는 새 키를 만들거나 공개 키를 교체하지 않는다.
개인 키를 출력하거나 커밋하거나 로그에 남기지 않는다.

개발 빌드는 기존과 같이 임시 서명이다. Apple Developer ID 서명·공증을 추가할 때에는
`FEEDEX_MAC_SIGN_IDENTITY`를 지정하고 공증 절차를 별도로 수행한다.

## 알림 (2.4 이상)

새 글은 기존 기기 동기화에서 감지하며 서버 푸시를 쓰지 않는다. 앱 내부에서 macOS UserNotifications로 보낸다.
새 글 제목 알림을 켜거나 ‘알림 허용 창 열기’를 누르면 macOS 권한을 요청한다.
이미 거부한 경우에는 시스템 알림 설정을 열며, 허용 후 앱으로 돌아오면 스위치 상태가 갱신된다.
알림 클릭은 같은 계정의 해당 글만 열고, 다른 계정의 알림으로 계정을 전환하지 않는다.
